# RISC-V RV32I on TON

Экспериментальная реализация **RISC-V-RV32I подобного процессора внутри TON smart contract**, написанного на **Tolk**.

Проект реализует интерпретатор машинных инструкций RV32I непосредственно в TON Virtual Machine (TVM).

Идея проекта — хранить состояние виртуального процессора в состоянии смарт-контракта и выполнять RISC-V машинный код непосредственно внутри блокчейна.

## Архитектура

Состояние виртуального процессора хранится непосредственно в storage TON-контракта.

Регистры оптимизированы для хранения в TVM:


x1–x4    → packed uint256
x5–x8    → packed uint256
x9–x31   → cell

Программная память и память данных представлены структурами TON Cells.

Таким образом, виртуальный процессор не является отдельной программой, запущенной вне блокчейна — его состояние является частью состояния самого смарт-контракта.

Команды управления

l<hex>,<hex>...  — загрузить программу
r                — выполнить до 100 инструкций
s                — выполнить 1 инструкцию
h                — показать x1 (hex)
g                — показать x2 (hex)
3                — показать x3 (hex)
5                — показать x5 (hex)
m                — показать RAM[PC] (hex)
get_state        — полное состояние процессора

Загрузка программы

Программа загружается командой:

l<instruction>,<instruction>,...

Инструкции разделяются запятыми.

Каждая инструкция представляет собой 8 hex-символов, то есть 32 бита.

Максимальный размер одной загрузки:

20 инструкций

Пример:

l00500093,00300113,002081B3

Это загружает:

ADDI x1,x0,5
ADDI x2,x0,3
ADD  x3,x1,x2

После загрузки программа ещё не выполняется.

Для запуска используется:

r

Для выполнения одной инструкции:

s

Hex-вывод

Все значения регистров выводятся в hex-формате.

Отрицательные значения используют представление two's complement, соответствующее 32-битной арифметике RV32.

Например:

-1   = ffffffff
-64  = ffffffc0

Сохранение состояния

Состояние виртуального процессора сохраняется между транзакциями.

Это позволяет выполнять длинные программы по частям:

r
r
r
...

Между вызовами сохраняются:

- "PC"
- регистры
- instruction RAM
- data memory
- состояние "halted"

Состояние процессора является частью storage смарт-контракта.

Пример

Простейшая программа:

l00500093,00300113,002081B3

После:

r

получаем:

x1 = 00000005
x2 = 00000003
x3 = 00000008

Fibonacci

В качестве интеграционного теста использовалась программа вычисления Fibonacci.

Для "n = 10" процессор корректно получил:

x2 = 89

Этот тест одновременно проверяет работу арифметических операций, регистров, сравнений, условного перехода и циклического выполнения.

Вызов функции

Поддерживаются "JAL" и "JALR", что позволяет реализовывать обычный механизм вызова и возврата из подпрограмм.

Пример:

l00500093,00C001EF,00700213,0100006F,00108133,00018067

Разметка программы:

PC  0   ADDI x1,x0,5       x1 = 5
PC  4   JAL  x3,12         x3 = 8, переход на PC 16
PC  8   ADDI x4,x0,7       x4 = 7 после возврата
PC 12   JAL  x0,16         переход в конец
PC 16   ADD  x2,x1,x1      функция: x2 = 10
PC 20   JALR x0,0(x3)      возврат на PC 8

Таким образом, "x3" используется как link register для хранения адреса возврата.

Память

Реализована byte-addressable data memory с little-endian представлением.

Поддерживаются:

LB
LH
LW
LBU
LHU

SB
SH
SW

Например, сохранение:

0x12345678

в память приводит к расположению байтов:

78 56 34 12

что соответствует little-endian представлению RV32.

Регистры

Процессор предоставляет 32 регистра:

x0
x1
x2
...
x31

"x0" соответствует нулевому регистру RISC-V:

- чтение "x0" всегда возвращает "0"
- запись в "x0" игнорируется
- значение "x0" не изменяется инструкциями

Выполнение

Максимальное количество инструкций за один вызов:

100

Команда:

r

выполняет до 100 инструкций.

Если программа длиннее, её можно продолжить следующим вызовом "r", поскольку "PC", регистры и память сохраняются в storage.

Команда:

s

выполняет только одну инструкцию.

Ограничения

Это экспериментальная реализация, а не полноценная реализация всей экосистемы RISC-V.

На текущем этапе отсутствуют:

- "BLTU"
- "BGEU"
- "FENCE"
- полноценная обработка "EBREAK"
- CSR
- interrupts
- MMIO
- полноценная система исключений и traps
- привилегированные режимы

Известные особенности

- "EBREAK" в текущей реализации трактуется как "HALT"
- "FENCE" не реализован
- "MAX_RAM = 20" инструкций
- "MAX_MEM_BYTES = 80" байт data memory
- выполнение "r" ограничено 100 инструкциями за один вызов
